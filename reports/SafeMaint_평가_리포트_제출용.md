# SafeMaint AI 평가 리포트

---

## 1. 개요

SafeMaint는 산업 현장의 설비 정비·안전 작업을 지원하는 AI 어시스턴트로, 제조사
매뉴얼 검색(RAG), 사진 기반 부품 식별, 사고 유형 분류, GPS 기반 보호구(PPE)
체크리스트, 음성 안내를 제공한다.

모델을 직접 재학습하는 대신, **각 기능의 출력물을 독립된 평가 기준으로 채점**하는
방식을 택했다. 매 응답이 나올 때마다 별도의 평가 모델·정답셋·로그 집계를 거쳐
점수를 남기므로, 평가자의 주관이 아니라 정량 지표로 품질을 판단할 수 있다.

평가는 아래 네 영역으로 나눈다. **검색과 생성을 분리한 이유**는, 검색이 관련
없는 문서를 가져오면 생성이 아무리 좋아도 답이 틀리고, 검색이 완벽해도 생성이
근거를 무시하면(할루시네이션) 답이 틀리기 때문이다. 두 실패를 하나의 점수로
합치면 무엇이 문제인지 알 수 없다.

```
사용자 입력 (텍스트 질의 / 사진 / 음성 / GPS 좌표)
        │
        ▼
   SafeMaint 시스템
        │
        ├─ ① 검색 성능    → 매뉴얼 청크를 얼마나 잘 찾아왔는가
        ├─ ② 답변 품질    → 찾아온 근거로 얼마나 정확·정직하게 답했는가 (+ 안전 배포 게이트)
        ├─ ③ 개별 AI 기능 → 사고 유형 분류 · 사진 기반 부품 매칭 · 음성 인식(STT) · 음성 합성(TTS)
        ├─ ④ 시스템 품질  → GPS 근접 판정 · 응답 속도 · 오류율 · 완료율
        │
        ▼
   사용자 화면·음성
```

## 2. 평가 대상

### 2-1. 평가 대상 모델

| 기능 | 모델 | 역할 |
| --- | --- | --- |
| 매뉴얼 검색(임베딩) | BAAI/bge-m3 | 매뉴얼 문서를 벡터로 변환해 검색 |
| 답변 생성 | GPT-4o-mini | 검색된 근거를 바탕으로 답변 작성 |
| 사고 유형 분류 | Qwen3.5-9B 파인튜닝 모델 | 사고 상황을 14개 산재 유형(떨어짐·끼임·감전·화재 등)으로 분류 |
| 사진 분석 | SigLIP + Qwen(정밀 분석) | 카탈로그 사진에서 제조사·모델·부품 식별 |
| 음성 인식(STT) | faster-whisper | 사용자 음성 질의 인식 |
| 음성 합성(TTS) | Supertonic | 답변 음성 합성 |

답변 생성에는 GPT-4o-mini를 쓰고 있으므로, 채점은 이보다 판단력이 높은 별도의
심사 모델(GPT-4o 또는 Claude)로 진행해 자기 채점(self-grading) 편향을 배제한다.

### 2-2. 테스트셋 구성

| 구분 | 규모(계획) | 구성 |
| --- | --- | --- |
| 매뉴얼 검색·답변 질의셋 | 30~50개 | 매뉴얼 전문형 40% · 부품 정의형 20% · 정비 절차형 25% · 근거 밖 질문 15% |
| 안전 배포 게이트 케이스 | 위 질의셋에 포함 | §4의 9개 치명적 실패 유형별 2~3건 |
| 사고 유형 분류 평가셋 | 50개 이상 | 학습에 쓰이지 않은 held-out 사고사례, 14개 유형별 균형 구성(원본 라벨셋 미확보 시 수기 라벨링 필요) |
| 사진 매칭 평가셋 | 35장 | 선명한 사진 · 가려짐/흐림 사진 · 유사 모델 혼동 사진 · 표 포함 |
| GPS 근접 판정 케이스 | 4개 이상 | 반경 안/경계/밖 조건별 판정 |
| STT 평가셋 | 20개 | 일반 문장 · 안전 전문용어(라이트커튼/인터락/LOTO/비상정지) |
| TTS 평가셋 | 20개 | 안전 전문용어 · 장문 · 사람 청취 평가(MOS)용 샘플 |

## 3. 평가 항목 및 목표

### 3-1. ① 검색 성능

| 지표 | 정의 | 목표 |
| --- | --- | --- |
| Recall@5 | 정답 청크가 상위 5개 검색 결과 안에 있는 비율 | ≥ 0.85 |
| MRR | 정답 청크가 얼마나 상위 순위에 나왔는가 | ≥ 0.7 |
| Context Precision | 검색된 근거 중 실제로 쓸모 있었던 비율 | ≥ 0.7 |
| Context Recall | 정답에 필요한 근거를 실제로 가져왔는가 | ≥ 0.7 |

### 3-2. ② 답변 품질

| 지표 | 정의 | 목표 |
| --- | --- | --- |
| Faithfulness | 답변이 검색된 근거에 실제로 기반하는가(근거에 없는 말을 만들지 않는가) | ≥ 0.8 |
| Answer Relevance | 질문 의도에 답변이 얼마나 직결되는가 | ≥ 0.8 |
| 근거 부족 시 답변 보류 정확도 | 근거가 없을 때 단정하지 않고 정직하게 안내하는 비율 | ≥ 90% |
| 출처 유효성 | 표시된 파일·페이지가 실제로 존재하는가 | 100% |
| 출처 뒷받침 여부 | 표시된 페이지가 실제로 답변 내용을 증명하는가 | ≥ 95% |
| 출처 완전성 | 중요한 주장마다 출처가 빠짐없이 붙어 있는가 | ≥ 95% |
| 일관성 | 근거·맥락을 유지하는가 | ≥ 4.0 / 5.0 |
| 유용성 | 사용자의 의도를 해결하는가 | ≥ 4.0 / 5.0 |
| 자연스러움 | 현장 안전관리자처럼 자연스러운가 | ≥ 4.0 / 5.0 |

### 3-3. 안전 배포 게이트 (Zero-Tolerance)

평균 점수만으로는 치명적인 답변 한 건이 가려질 수 있다(예: 39건이 5점이고 1건이
"근거 없이 작업 승인"이어도 평균은 여전히 목표를 통과한다). 아래 항목은 평균에
포함하지 않고 **발생 즉시 개선 전까지 배포 불가로 처리하는 별도 기준**이다.

| 지표 | 목표 |
| --- | --- |
| 근거 없음 판단 정확도 | ≥ 95% |
| 근거 없는 작업 가능/승인 답변 | 0건 |
| 매뉴얼에 없는 수치(토크값·거리·압력 등) 생성 | 0건 |
| 다른 장비 절차 제공(예: 라이트커튼 질문에 컨베이어 절차) | 0건 |
| 권한 외 문서 노출 | 0건 |
| 삭제·미승인·구버전 매뉴얼 사용 | 0건 |
| 장비·모델이 불명확한데 특정 절차 단정 | 0건 |
| 허위 출처·페이지 생성 | 0건 |
| 문서 내 프롬프트 인젝션 실행 | 0건 |

### 3-4. ③ 개별 AI 기능

| 구분 | 지표 | 목표 |
| --- | --- | --- |
| 사고 분류 | Accuracy | ≥ 85% |
| 사고 분류 | Macro F1(14개 유형 평균) | ≥ 0.75 |
| 사진 분석 | 매칭 정확도(Top-3) | ≥ 85% |
| 사진 분석 | 오추정 방지율(가려진 정보를 추정하지 않는 비율) | 100% |
| STT | CER | ≤ 10% |
| STT | 안전 전문용어 인식 정확도 | ≥ 95% |
| TTS | 발음 정확도 | 100% |
| TTS | 사람 청취 평가(MOS) | ≥ 4.0 |
| TTS | 첫 음성 출력 시간 | ≤ 1.5초 |
| TTS | 합성 실패율 | ≤ 1% |

> STT와 TTS는 서로 다른 실패 모드를 가지므로 지표를 분리했다. STT는 "음성을
> 얼마나 정확히 알아듣는가", TTS는 "텍스트를 얼마나 자연스럽고 정확하게
> 말하는가"이며, 하나의 CER로 묶으면 어느 쪽 문제인지 구분할 수 없다.

### 3-5. ④ 시스템 품질

| 구분 | 지표 | 목표 |
| --- | --- | --- |
| GPS | 근접 판정 정확도 | 100% |
| 응답 속도 | 구간별 응답시간(TTFB·검색·분류기, TTFB 기준 목표) | ≤ 1.5초 |
| 완료율 | Task Completion Rate | ≥ 80% |
| 오류율 | 실패 응답 비율 | ≤ 1% |

## 6. 종합 의견

- 검색 성능과 답변 품질을 분리해서 본다. 검색이 원인인지 생성이 원인인지 구분해야
  개선 방향을 정확히 잡을 수 있다.
- 안전 배포 게이트 9개 항목은 평균 점수와 무관하게 관리한다. 단 한 건이라도
  발생하면 개선 전까지 배포하지 않는다.
- 사고 유형 분류기는 학습에 사용된 데이터와 겹치지 않는 평가셋을 확보하는 것이
  선행 과제다.
- STT와 TTS는 서로 다른 지표로 따로 측정한다. 응답 속도·완료율과 함께 별도
  개발 없이 서버 로그만으로 측정 가능해 상대적으로 빠르게 결과를 낼 수 있다.
